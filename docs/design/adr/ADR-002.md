# ADR-002: Layered monolith: React SPA + Express REST API

- **Status:** accepted
- **Source:** T04-PA3 Section 3.6

## Context

C-01 fixes React (Vite) + Tailwind CSS and Node.js + Express. The open question is how to structure them. The team has 4 members and a fixed effort budget (C-06), only free hosting (C-05, OE-03, OE-04), and needs responsive pages (NFR-06) and a 3 s response time (NFR-01).

## Decision

Build one single-page application (Web App, on Vercel) and one REST API (API Application, on Render), organised in feature modules with the layers controller → service → repository (§3.1, §3.4).

## Alternatives considered

- Microservices (one service per feature): lost because each service would need its own free-tier instance that sleeps (OE-04), calls between services add latency against NFR-01, and the lecture guideline is that a small team starts with a modular monolith.
- Server-rendered pages (Express + templates, no SPA): lost because C-01 names React and the multi-step donation form and the 360 px layouts (NFR-06) are easier to build as SPA components.

## Consequences

- + One code base and one deployment per tier; the module boundaries (§3.4) keep features separate and testable.
- − All API modules scale together and one fault can stop the whole API; acceptable for 20–50 users (NFR-01, NFR-04).
